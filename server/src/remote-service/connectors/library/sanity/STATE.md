## Incremental polling

- **Supported:** YES (2026-07-31). Driver field = `_updatedAt` — service-guaranteed system field, annotated `x-scratch-last-modified-field`; `incrementalPullSupport()` returns SUPPORTED unconditionally and `metadata.incrementalPull: true`.
- **Mechanism:** server-side GROQ clause `dateTime(_updatedAt) >= dateTime($since)` ANDed into the `_id`-cursor pagination query (`sanity-incremental.ts`; `dateTime()` on both sides because Sanity emits seconds precision while the watermark carries millis). Watermark captured before the first page; 60s clock-skew margin subtracted from `since`; inclusive predicate re-pulls a small overlap window that idempotent commits absorb.
- **Verified live 2026-07-31 ×3:** builder run (bootstrap full → API-side edit → `pull --mode incremental` picked it up; `DataFolder.lastIncrementalPullAt` stamped) and twice more by the adversarial review (direct mutations picked up; future-cutoff probe returns `[]`).
- **Deletions:** not detectable incrementally (no tombstones in the data API) — reconciled by periodic FULL_PULL.

## Edge cases discovered

- **Viewer-role tokens 403 all mutations** (`Insufficient permissions; permission "create" required`) — surface as a clear connect-time or publish-time error. The audit-creds token hit this 2026-07-31.
- **Type discovery is document-driven**: a `_type` with zero documents doesn't exist as far as the API is concerned — an empty project lists no tables. Expected, but surprising in the picker.
- **Slice bounds can't be GROQ params** (`[0...$n]` is a syntax error) — page size must be inlined into the query string.
- **`system.*` types leak into `*` queries**: even a fresh project carries `system.group` + `system.retention` documents, and they showed up as tables in the CLI picker (2026-07-31). Fixed: the internal-type filter now excludes both `sanity.*` and `system.*` prefixes. Watch for other reserved namespaces (e.g. a `media.tag` from the media plugin is arguably user data — undecided).
- **Deployed schema doc `_type` mismatch**: `sanity schema deploy` stores the doc with `_type: "system.schema"` live (docs say `sanity.workspace.schema`) — the connector fetches by id path (`_.schemas.**`), the stable contract, not by `_type`.
- **Deployed schema omits default titles**: a declared field title equal to Sanity's own humanization of the name (e.g. "Meta Title" on `metaTitle`) is dropped from the serialized payload — display fallback must humanize regardless (it does).

## Gotchas

- **CLI `linked add` table-id syntax**: the repeatable `--table-id` flag takes ONE remoteId _segment_ per flag — `--table-id hkcx2dra --table-id production --table-id post` — NOT the comma-joined string the `available` output displays. Passing `"a,b,c"` as one flag sends a 1-element remoteId and the connector's parse rejects it (one add call per table).
- Robot tokens can list their own project via the management `GET /projects` — that's what makes single-param (token-only) connections work.
- Dataset `production` here has `aclMode: public` — unauthenticated reads succeed, so only management-API calls prove the token itself.
- Draft documents (`drafts.<id>`) are invisible at `perspective=published`; a Studio user's unpublished edits won't appear in pulls.
