## Service & connection
- **Login:** `https://app.companycam.com` · **API docs:** `https://docs.companycam.com` (reference index also at `https://companycam.readme.io/llms.txt`).
- **API key source:** CompanyCam web app → profile menu → **Access Tokens** (`https://app.companycam.com/access_tokens`) → **+ New Token** → (leave "read only" unchecked) → **Create Token**, then copy. Requires **Admin** role; available on **all plans**. The token is a **long-lived personal access token** (no expiry tied to a login session). **Never record the key itself.** To inspect a live one, decrypt `ConnectorAccount.encryptedCredentials` (AES-256-GCM, key `ENCRYPTION_MASTER_KEY` in `server/.env`, AAD `connector-account`; `server/tools/decrypt-credentials.js`).
- **Accounts used:** initial run on a "Whalesync Testing" trial; that trial expired (whole account went read-only), so the run moved to a fresh "Whaleform Inc" trial — a **new Access Token** was generated and swapped onto the same connection via `PATCH …/connections/:id` `{userProvidedParams:{apiKey}}`. Connector behavior was identical across both accounts (incl. the ChecklistTemplates 401), confirming findings aren't account-specific.
- **Auth header style:** `bearer` (`Authorization: Bearer <token>`).
- **API traits:** pagination `page` (`?page=N&per_page=M`, terminates on empty page; also supports `modified_since` for incremental and `query` filters) · OAuth-only? **no** (PAT available; OAuth exists only for partner apps) · base URL `https://api.companycam.com/v2`. List responses are **bare top-level JSON arrays** (Rails-style) — apiget handles these natively. Record IDs are **strings** at `id`.
- **Feature flag:** `ENABLE_GENERIC_CONNECTOR` enabled for test user? **yes** (confirmed by user).
