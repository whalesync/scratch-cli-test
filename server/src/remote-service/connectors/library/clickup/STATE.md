### Structural facts (how ClickUp models things — confirmed live)
- **A subtask IS a task with a `parent`.** Verified: creating `POST /list/{id}/task` with `parent: <taskId>` returns a normal task whose `parent` = the parent id and `top_level_parent` = the root ancestor; it comes back from the same list endpoint with `subtasks=true`, in the same shape. **Implication:** subtasks need *no* special object or codepath — they ride the normal Task path; only the `parent`/`top_level_parent` fields differ. (Reparenting via `parent` is read-only in v1.)
- **Custom field values live in an array, not as top-level keys** — `custom_fields: [{id,name,type,value}]` — so each value is addressed by field id (`POST /task/{id}/field/{field_id}`), unlike a flat-key service (Airtable). Stored verbatim.
- **Statuses are per-list**, not global — a status name valid on one list (e.g. "to do") may not exist on another; a create with an unknown status 400s.
- **A token can hold multiple Workspaces (`GET /team` → many), so Workspace MUST be a path segment** — else same-named spaces/lists across workspaces collide. The kind + team id are encoded in `remoteId` (`['list', teamId, listId]` / `['users', teamId]` / `['doc', teamId]`) so `fetchJsonTableSpec` can resolve the workspace name (`GET /team`) for the path and dispatch the codepath.
- **Docs are on a different API version (v3)** with a different shape — handled by their **own codepath** (not bent through the v2 task code).
- **CLI multi-segment `remoteId`:** `scratchmd linked add` takes `--table-id` **repeatably**, one per `remoteId` component (e.g. `--table-id list --table-id <teamId> --table-id <listId>`); passing the comma-joined string as one value hits the legacy single-segment path and fails.

## Foreign keys / associations
- ClickUp relationships are a **custom field of type `tasks`** (links a task to other tasks), not a top-level field. Because custom-field values live in the verbatim `custom_fields` array (not a named schema property), a declarative `x-scratch-foreign-key` doesn't cleanly target them in v1 — relationship writes go through the custom-field value path. **Coverage: ⬜** (needs a relationship field seeded via UI).
- `parent` (subtask link) is read-only in v1.

## Edge cases discovered
- **Sprint Points / Time Estimates ClickApp gating (ITEM_227).** Sending `points`/`time_estimate` to a list whose ClickApp is disabled **400s the whole write**. The connector now only sends a *non-null* value the user explicitly set (a verbatim pull has these as null and never trips it); a genuine value on a disabled list still surfaces the API error rather than being silently dropped. (Generalizable: ClickUp/other services feature-gate fields per-container — a single gated field can fail the whole record write, GHL-style.)
- **due_date day-boundary normalization.** Without `due_date_time:true`, ClickUp snaps `due_date` to a day boundary in the workspace timezone (e.g. `1781000000000` → `1780966800000`), so a write doesn't round-trip exactly. v1 sends `due_date` as-is (day precision).
- **status/priority read-shape ≠ write-shape.** Both are objects on read but a name-string / int on write — the connector translates in `createRecords`/`updateRecords`; the stored file keeps ClickUp's read shape.
- **Custom fields are UI-only.** The API reads custom field definitions and sets values, but cannot create the fields — seed them through the ClickUp UI.
- **Filenames are a name-slug** (`task-1.json`), not the task id; the `id` is inside the file. New records receive their id after create.
- **Masked token field.** The API-token settings input shows a masked value (`pk_…****…`); only the **Copy** button yields the real token.

## Gotchas
- **CLI publish needs working gcloud ADC (environment, not connector).** `scratchmd files upload` → `POST /cli/v1/workbooks/:id/upload-patch/init` issues a **GCS presigned PUT URL** via impersonated gcloud creds. When those expire you get a **500** with `invalid_rapt` / `SigningError` from `object-storage.service.ts`. Fix: `gcloud auth application-default login` **and restart the server** (the running process caches ADC at boot). Hit + resolved during this run. Affects **every** connector, not just ClickUp.
- The connector pulls with `subtasks=true&include_closed=true` so a full pull captures everything; tasks page at 100/page (`last_page`).
- Rate limit: ClickUp Free = 100 req/min per token; connector rate-limited to 90/60s and honours `X-RateLimit-Reset` / `Retry-After` on 429.
