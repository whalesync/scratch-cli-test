## ⚠️ Architectural note — this is NOT an HTTP/REST connector
Framer's **Server API** (beta) is a **stateful WebSocket** transport driven by the official **`framer-api`** npm SDK (not axios/REST). You `connect(projectUrl, apiKey)` → get a `Framer` client that mirrors Framer's Plugin API, run operations, then `disconnect()`. Implications baked into the connector design:
- The connector wraps the **`framer-api` SDK**, not `createApiClient`/axios. The server is ESM (`"type":"module"`, `module: NodeNext`) and already ships SDK-based connectors (`@notionhq/client`, `@linear/sdk`, `stripe`), so an ESM-only SDK dep is fine.
- **Cold starts** (~1–2 s on first connect; warm reconnect within a window). So the connector should `connect()` **once per operation** (one pull, one publish batch), iterate, then `disconnect()` — not connect per record.
- The "v8 sandbox / runs your code" language in Framer's FAQ refers to **their** server executing plugin-style calls; from our side it's just an RPC client over WSS. We do not ship code to them.

**Read = target SLUG; write = target item ID.** The connector stores the verbatim slug and translates slug→id on write (`getWriteTranslationMaps` fetches the target collection's items). **Cross-record FK resolution (sync / Live Export) — resolved, DEV-11085.** The annotation also declares `targetKeyPath: 'slug'`, the generic contract for "this reference names its target by a field other than the target's remote id". The FK phase indexes the referenced folder by that path before the destination lookup, so a slug resolves to the target item's id and on to the destination record. Without it the resolver assumed the slug WAS a remote id, missed every reference, failed the table sync, and the whole export published zero records. Nothing connector-side translates on read — the stored slug stays verbatim.

## Edge cases discovered
- **Read shape ≠ write shape — enum & references (id-translation on write).** Framer reads enum values back as the **case name** (`"Live"`) and reference values as the target item's **slug** (`"design"`), but `addItems` **requires the case id / item id** on write (`"Expected a valid enum case"` / `"Bad reference, ID: …"`). The connector stores the verbatim read shape and maps name/slug→id on write (`getWriteTranslationMaps` + `translateValueToId`). The maps key both the read value AND the id, so a value that's already an id passes through. Because read is always name/slug, round-trips are clean (no phantom diff).
- **Value normalization → transient phantom diff (date / color / formattedText).** Framer rewrites these on write: `date` `2026-12-25`→`2026-12-25T00:00:00.000Z`; `color` `#FF0000`→`rgb(255, 0, 0)`; `formattedText` gains `dir="auto"` on block tags. The write lands, but the working copy (typed value) differs from the normalized read-back, so the file shows as `unpublished` until the next pull reconciles it (the connector's update read-back makes `main` canonical). Same family as Affinity date-snapping.
- **Silent success that didn't land — failed write batch reports "Published".** `addItems` is atomic per item: one invalid field (e.g. an untranslated enum) rejects the **whole** item, but the publish job logs a `warn: Batch failed` and still reports `Published 1 connection(s)`. **Always confirm in the service API, not the CLI line.** The pre-translation bug surfaced exactly this way.
- **Empty fields omit `value`.** An unset field reads back as `{ "type": "file" }` (no `value` key) — schema makes the entry's `value` optional.
- **Image/file re-hosting.** Writing an external image URL makes Framer download + re-host it under `framerusercontent.com`; the read-back URL differs from the one sent (expected, not a bug).
- **Unicode/emoji preserved** in formattedText (utf8mb4) — `✨` round-trips intact.
- **`listTables` (available) list is briefly stale** after creating a collection via the SDK — newly-created collections didn't appear in `linked available` for a short window (server-side list cache), though linking by explicit table-id worked immediately.
- **Field clears: empty-string works, `null` is dropped (platform).** Setting a value to `""` clears it (verified: Website `https://framer.com`→`""` landed). Setting it to `null` is **silently dropped** — the CLI's merge-patch treats `null` as a key-delete and `computeChangedFields` ignores deleted keys, so the field is skipped and keeps its old value (verified: Count `99` stayed `99`). This is the cross-connector platform null-clear behavior (see `docs/connector-build.md`), not Framer-specific. To clear a field, send an empty value, not `null`.

### Bug-hunt session (2026-06-19) — found & fixed
- **BUG (fixed): Framer normalizes the slug on create, breaking read-back-by-slug.** `"Hello World!"` → `"hello-world"` (lowercase, ASCII space/punct → dash; unicode/emoji kept; duplicate slug throws). The original `createRecords` read back by the **sent** slug → miss → the create-read-back **threw spuriously on a successful create** and the new id was lost. **Fix:** `createRecords` now **id-diffs** — snapshot existing item ids, create, then the items whose id is new are the created ones, in INPUT order (verified `getItems` appends new items in creation order). Captures the id even when the slug was rewritten. (A slug edit on **update** normalizes the same way; harmless since update reads back by id.)
- **BUG (fixed): link schema's `format: 'uri'` rejected an empty/cleared link.** Framer returns `""` for a cleared link, and the `enforce_schema` validator enforces `format` → the **verbatim record failed its own schema** (Copper "schema rejects valid data" class). **Fix:** dropped `format: 'uri'` from the link value (the `url` column type still hints display). Regression-covered by a unit test with an empty link.
- **Hardening: `unsupported` field values are now read-only.** A field type the SDK doesn't model has an unknown write shape, so it's marked `x-scratch-readonly` (future-proofs against new Framer field types an older SDK version doesn't recognize).
- **Verified safe (no bug): update MERGES.** A partial-`fieldData` update preserves unsent fields (updating only `Count` kept Title/Active/Tags). So `updateRecords` sending only `changedFields` is **not** a data-loss risk.
- **Boundary values OK:** numbers `-42 / 0 / 1e15 / 3.14159` round-trip exact; a 5000-char string is preserved; an empty `multiCollectionReference` `[]` clears; a date **with a time** is preserved (no day-snapping; only date-only input defaults to midnight); a reference to a nonexistent target throws `"Bad reference"` (atomic, surfaced).

## Adversarial review (codex, 2026-06-19)
Ran `codex` adversarial challenge on the connector diff (12 findings). Dispositions:
- **Fixed:** disconnect-masks-error (wrap `framer.disconnect()` in `.catch`); enum/reference map collisions made deterministic (slug/name wins over id-passthrough); a **create read-back miss now throws** instead of returning an id-less record (would otherwise land a record with no remote id → duplicate on next pull).
- **Confirmed platform/v1 (documented, not connector bugs):** `null` wrapper-clear is a no-op (platform merge-patch, above); read-only top-level fields (`id`/`nodeId`/`slugByLocale`) are UI-prevented from editing (marked `x-scratch-readonly`); localization edits unsupported in v1.
- **Accepted trade-offs:** writes use one short-lived WebSocket **per op** (translation/upsert/read-back = 3 connects) — extra cold-start latency and a theoretical translation-vs-write race; consolidating to one connection per write is a worthwhile follow-up. Mixed mapped/unmapped multi-reference values poison the atomic item (better pre-validation diagnostics would help). A hand-malformed asset object without `url` would write `null` (clearing it).
- **Not applicable:** duplicate-slug/same-id-twice mis-pairing (Framer enforces unique slugs; one file = one id per batch); `changedFields`-omitted crash (the abstract contract requires it; matches Airtable).

## Gotchas
- **Folders showed the collection ID, not the name (CLI bug, fixed — not connector-specific).** The desktop labels a table folder by `DataFolder.name`. The server requires a non-empty name, and `scratchmd linked add` **defaulted the name to the table id** when `--name` was omitted (`scratch-git-2/src/cli/commands/linked.rs`), so CLI-linked Framer folders displayed `nB6mUeFWU` etc. (the path was always correct, `/Field Types`). The web "Add tables" UI passes the real display name, so normal users were unaffected. **Fixed** the CLI to default `--name` to the table's display name (collection name). Existing folders were renamed in place. Affects every connector linked via the CLI without `--name`, not just Framer.
- **ESM-only SDK in a CJS runtime.** `framer-api` is pure-ESM with top-level await; the NestJS server runs as CommonJS, so a static import crashes boot with `ERR_REQUIRE_ASYNC_MODULE`. Loaded via a `Function('return import("framer-api")')` dynamic import (see `framer-api-client.ts`). Same reason the live jest spec can't run (jest is CJS; `--experimental-vm-modules` then breaks the CJS `nanoid` require).
- **No delete-collection API.** Collections can be created (`createCollection`) but not deleted via the SDK — integration/test fixtures are durable; round-trip items, not tables.
- **`getItems()` returns all items at once** (no pagination cursor in the SDK) — fine for the test collections; watch memory on very large collections.
