**Org-wide rate/quota limits.** Stripe enforces several ceilings at once: **100 requests/second globally in live mode but only 25/s in sandbox**, plus **25/s for any single endpoint** regardless of mode, plus undocumented *concurrency* ceilings surfaced via the `Stripe-Rate-Limited-Reason` header (`global-concurrency` / `endpoint-concurrency`). A pull walks one entity's endpoint at a time, so the per-endpoint 25/s is the ceiling that actually binds — hence `rateLimiterSpec` of 20/s. Stripe sends **no `Retry-After`**; its guidance is exponential backoff with jitter. Note that `lock_timeout` is *also* returned as 429 but is object contention, not rate limiting — backoff helps, but sustained contention needs serialized writes. Separately, reads are metered against a rolling 30-day allocation (avg 500 per transaction, floor 10,000/month) — a billing quota, not a rate limit. https://docs.stripe.com/rate-limits

## Edge cases discovered
- **A subscription's billing period lives on its items.** The Basil release removed `subscription.current_period_start|end`; each item carries its own. The default view reads them from the first item (`items.data.0.current_period_start|end`, "Current Period Start|End"), which is the subscription's period unless it uses flexible billing mode. The record stays verbatim; the generic path layer resolves a numeric segment as an array position (`getSchemaAtFieldPath`, `resolveSchemaTypeAtPath`). The desktop grid's `getByPath` never indexes arrays positionally, so those two columns show blank there.
- **Embedded lists stop at 10 entries.** A subscription's `items`, an invoice's `lines`, and a credit note's `lines` come back with `has_more: true` past 10; the client pages the rest from `/v1/subscription_items?subscription=`, `/v1/invoices/{id}/lines`, or `/v1/credit_notes/{id}/lines` and splices it in (`TRUNCATED_EMBEDDED_LIST_SOURCES`).
- **`discounts` are ids, not objects.** Subscriptions and invoices return `di_…` ids unless the request expands `discounts`. The connector doesn't expand them: an expansion needs a Stripe App permission for every object it expands, and an unverified one could fail the whole Subscriptions or Invoices pull. Amounts per discount are in `total_discount_amounts`; the coupon behind a discount is not exported.
- **Refunds and balance transactions have no `livemode`.**
- **Every Stripe timestamp is a Unix-epoch integer in SECONDS**, not an ISO string — Stripe has no ISO date type. The schema records that as `x-scratch-connector-data-type: unix-timestamp-seconds` (`STRIPE_UNIX_TIMESTAMP_DATA_TYPE`); the default view reads the annotation and emits a date column backed by an `epoch_to_iso` codec. Annotating `format: 'date-time'` instead would be WRONG twice over: the raw value isn't a string, and it would create a real date column while still handing the destination the bare integer (DEV-11145).
- **Stripe caps every free-text string at 350 chars**, so `text` (not `longText`) is the honest declaration for a description — the multi-line data loss seen on Airtable was the destination pack choosing `singleLineText`, not a Stripe-side problem (DEV-11147).

## Gotchas
- **Client secrets are hidden.** `payment_intents.client_secret` and `invoices.confirmation_secret` are credentials (with the publishable key they retrieve and confirm the payment), so the default view hides them and Live Export never offers them. They became exportable only when the schema started declaring every field. An event's `data` is a snapshot of the object that changed, secrets included (every `payment_intent.*` event holds a `client_secret`), so the Events table hides `data` too and exports the object's id and type (`data.object.id`, `data.object.object`) instead. Stripe's API error objects (`payment_intents.last_payment_error`, `invoices.last_finalization_error`) can embed a whole payment intent, setup intent, or source, so they export one column per scalar field (code, decline code, message, …) with the embedded objects left in the hidden raw column. A test fails if any exported column's schema can hold a `client_secret` at any depth.
- **An `x-scratch-*` key on a non-nullable object hides what's inside it.** The schema flattener treats such an object as one opaque value, so a foreign key nested in it (`promotion_codes.promotion.coupon`) would never be found. `buildStripeRecordSchema` gives every non-nullable top-level object the same one-arm `anyOf` wrapper a nullable one has, and puts the read-only flag on the wrapper.
- **Hidden ≠ collapsed.** A column marked `hidden` in the default view is dropped from Live Export field selection entirely, so the user is never offered it. Keep `HIDDEN_FIELDS` to genuine plumbing (`object`, `livemode`, `invoice_prefix`); anything hidden beyond that is silently unexportable (DEV-11148). `metadata` is NOT plumbing: it holds the account's own keys (CRM ids, internal user ids), so it exports whole as one column (jsonb on Postgres, text where the destination has no JSON column). Its keys are open-ended and Stripe has no endpoint that lists them, so one column per key would mean scanning pulled records.
- **The default view must read the serialized JSON-Schema `type` keyword, never TypeBox's `Kind` symbol.** The view is regenerated from a schema that may have been JSON-parsed off disk, where symbols are gone — a `Kind`-based mapping silently types every column `undefined` there (this was live until the DEV-11145 pass; the `stripe-products` view-codec golden shows the before/after).

## OAuth (final milestone — create the client with the user, or document what it takes)
API-key (`user_provided_params`) connection covers all testing; OAuth is a pre-release nicety done *with* the user.
- **Requires:** nothing new on Stripe's side. Scratch shares **Whalesync's published Stripe app** (`whalesync/extensions/stripe`, owned by the Whalesync Stripe Apps account `acct_1UTnbqPi0s0AjjMs`). Its manifest already lists Scratch's redirect (`/oauth-callback/connector/stripe` on `app.`/`test.whalesync.com`), and its 20 read permissions cover all seven tables (prices under `plan_read`, subscription items under `subscription_read`). The app is read-only, as is this connector.
- **Endpoints:** authorize `https://marketplace.stripe.com/oauth/v2/authorize` in production, the app's External test link (`…/oauth/v2/chnlink_61VdC9PS9Zq71csij41Pi0s0AjjMsRgW/authorize`, env `STRIPE_OAUTH_AUTHORIZE_URL`) elsewhere · token `https://api.stripe.com/v1/oauth/token` · redirect URI = `REDIRECT_URI_WHALESYNC` + `/oauth-callback/connector/stripe` (Whalesync's callback hands Scratch's state back to Scratch or Live Export).
- **App / client:** `STRIPE_OAUTH_CLIENT_ID` = the app's client id for the environment's mode (production live `ca_VUnc4j…`, elsewhere test-mode `ca_VUnckA…`); `STRIPE_OAUTH_CLIENT_SECRET` = the Whalesync Stripe Apps account's `sk_live_…` / `sk_test_…` key (the same values as Whalesync's `connector-oauth_stripe` secret; restricted keys are refused). Not `STRIPE_API_KEY`, which is Scratch's billing key.
- **How it works** (`server/src/oauth/providers/stripe-oauth.provider.ts`): authorization code with PKCE. The token endpoint takes the secret key as the HTTP Basic user name and only `grant_type` + `code`/`refresh_token` (+ `code_verifier`). Stripe sends no `expires_in`, so tokens are recorded as 1-hour tokens; refresh tokens rotate on every refresh. The installing account (`stripe_user_id`) is kept in `oauthWorkspaceId`.
- **Status:** provider wired, unit-tested; consent flow not yet run live.
- **Permissions for the tables added 2026-11-03:** Refunds (`charge_read`), Disputes (`dispute_read`), Credit Notes (`credit_note_read`), Coupons (`coupon_read`), Promotion Codes (`promotion_code_read`), Balance Transactions (`balance_read`), and Events (`event_read`) are all in the app's manifest, and Whalesync's own Stripe connector lists them through the same app. Subscription Schedules has no permission of its own in Stripe's list; it is assumed to fall under `subscription_read` and is unverified through OAuth.
- **Limits:** in production the sign-in reaches live mode only, so a test-mode account connects with a pasted secret key. A second sign-in to the same Stripe account (another Scratch connection, or a Whalesync one) may revoke the first's access tokens on refresh — untested.
- **Blockers:** `STRIPE_OAUTH_CLIENT_ID`/`_SECRET` must be filled in Secret Manager for `spv1eu-test` and `spv1eu-production`, then `terraform apply` per env.
