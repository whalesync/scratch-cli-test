## How the connector models Salesforce

- **Tables = sObjects**, from the org's `GET /sobjects` catalog (one call). Listed: every queryable + retrieveable,
  non-deprecated object that is either a **custom `__c` object** or **layoutable** (has page layouts = user-facing), plus a short
  core-CRM list. That keeps ~1,000 system objects (feeds, histories, shares, setup metadata) out of the picker.
  Grouped as `Core CRM objects` / `Custom objects` / `Other standard objects`. `wsId` = lower-cased API name
  (`account`, `invoice__c`); `remoteId` = `[ApiName]`.
- **Schema = the object's live describe** (`GET /sobjects/{object}/describe`): one top-level property per field, in
  describe order, after `attributes`. Custom fields and objects appear with no connector change.
- **Records are stored exactly as SOQL returns them** — `SELECT <every describe field> FROM <object> ORDER BY Id`.
  Verified key-for-key (order included) against the single-record `GET /sobjects/{object}/{id}`. The `attributes`
  block (`{ type, url }`) is part of every record Salesforce returns, so it is kept; its `url` embeds the API version.
- **Pagination**: `nextRecordsUrl` within a run; the resume point is `lastPulledRecordId` (`Id > …` on restart),
  because query cursors expire after 15 minutes idle. A resumed run keeps the original run's watermark.
- **Incremental**: `SystemModstamp > <since − 60 s>` (falls back to `LastModifiedDate`). Deletes are reconciled by the
  full pull (SOQL `query` omits recycle-bin records).
- **Writes**: sObject Collections, 200 records per request. Create and update are **all-or-none** (a rejected record
  rolls the batch back, so the publish runner's one-at-a-time retry can't duplicate anything); delete is not, and an
  already-deleted record counts as deleted. Creates and updates read the records back, so the returned files carry
  Salesforce-computed values.
- **Read-only / write-once** come from describe: `!createable && !updateable` → `x-scratch-readonly` (system, audit,
  formula, roll-up, compound fields); `createable && !updateable` → `x-scratch-write-once`. A changed read-only or
  write-once field fails the update with `NonWritableFieldEditError`; it is never dropped.
- **Required**: `createable && !nillable && !defaultedOnCreate` (minus checkboxes) is `required` in the schema.

## Auth

- **OAuth 2.0 web-server flow with PKCE** (`server/src/oauth/providers/salesforce-oauth.provider.ts`), using
  **Whalesync's Salesforce connected app** (system app generation 1, env `SALESFORCE_CLIENT_ID` / `_SECRET`, redirect
  `<REDIRECT_URI_WHALESYNC>/oauth-callback/connector/salesforce` — dusky forwards Scratch's state generically). No
  scope is requested; the connected app's own scopes apply and must include `refresh_token`/`offline_access` (the
  exchange fails loudly without a refresh token).
- **Sandbox**: the connect form's "Sandbox org" box (`salesforceSandbox`) sends authorize + code exchange to
  `test.salesforce.com`. It picks between two hard-coded hosts; it never supplies one. The choice is stored in the
  connection's extras (`{ sandbox }`), so a reconnect — whose form doesn't offer the box — signs in at the same host.
- **Instance URL**: the token response's `instance_url` (the org's My Domain) is persisted in `oauthWorkspaceId`. The
  connector calls the API there, and refreshes go there too (`<instance>/services/oauth2/token` serves production and
  sandbox alike). It must be a bare https origin on a Salesforce domain (`*.salesforce.com`, `*.force.com`,
  `*.cloudforce.com`, `*.salesforce.mil`, `*.sfcrmproducts.cn`): a connection edit can overwrite stored credential
  keys, and a refresh sends the system app's client secret to that host.
- **Token lifetime**: Salesforce sends no `expires_in`; a token lives for the org's session timeout (15 min–24 h,
  admin-set). The provider reports **15 minutes**, so the host refreshes ahead of any org's expiry.
- **Secrets**: Whalesync's connected-app client id and secret are in `SALESFORCE_CLIENT_ID` / `_SECRET` in `spv1eu-test`
  and `spv1eu-production` Secret Manager, and `terraform apply` has run in both, so OAuth works on test and production.

## Live Export (local, Salesforce → Postgres), 2026-10-27

Harness: `node tools/live-export-audit/audit.mjs --source SALESFORCE --dest POSTGRES --workbook … --source-connection …`
with a connection from `seeds/salesforce/create-oauth-connection.mjs`; tables Account, Contact, Opportunity, Case,
Lead, User.

- First run **Published 122 changes**, 0 failures. Row counts match Salesforce exactly (13/20/31/29/22/7).
- **29 FK constraints** created (Opportunity → Account/Contact/User, Contact → Account, Case → Account/Contact, Lead
  converted-ids, User → Account/Contact/User, self-links); joins resolve. FKs to objects outside the export
  (Campaign, Pricebook2, UserRole, Profile, …) are dropped, as designed.
- Datetimes land as `timestamp with time zone` with the right instant (`logicalType: datetime` works); dates exact.
  Address components export as columns; the hidden compound/system columns don't.
- 6 warnings: references to Salesforce's system users (e.g. Automated Process), which `SELECT … FROM User` doesn't
  return — accurate.
- **Second run is not a no-op: 57 updates, all `date` columns** (Birthdate, Close Date, SLA Expiration Date). That was
  the Postgres-destination `date` round-trip on a non-UTC host (`pg-common` read `date` as a JS Date at the server's
  local midnight), not this connector. Fixed for Postgres and Supabase in DEV-12576 (`ddc1f6d7a`).
- Harness fix made in passing: `audit.mjs` now matches a pending FK by `unresolvedLinkedTableRemoteId` the way dusky
  does; it used to drop every Salesforce/QuickBooks FK because their `linkedTableId` (lower-cased wsId) appears in no
  remote-id segment.

## Gotchas

- **Objects that reject an unfiltered query**: `ContentDocumentLink`, `ContentFolderItem` ("requires a filter by a
  single Id…") — listed disabled with a reason. `PendingOrderSummary` rejects `WHERE Id >` (only hit on a resumed pull).
  Of the objects the catalog flags `custom`, only `__c` ones are listed: a custom object's `__Share` / `__History` /
  `__Feed` / `__ChangeEvent` companions, big objects (`__b`), external objects (`__x`), platform events (`__e`) and
  custom metadata types (`__mdt`) aren't.
- **GET request-line limit**: Salesforce returns HTTP 431 past ~20,000 characters (measured), and a wide object's
  all-fields query can exceed it (`PermissionSetLicense` here; orgs with hundreds of custom fields on Account will).
  Queries over 15,000 encoded characters run as a GET subrequest inside `POST /composite` (verified with 47,000).
- **Read-only fields in a create are rejected even when null** (`INVALID_FIELD_FOR_INSERT_UPDATE`), so the create body
  leaves out read-only fields that are `null`; a read-only field with a value is still sent and rejected by name.
- **Daily API limit and concurrency limit share an error code** (`REQUEST_LIMIT_EXCEEDED`, HTTP 403): the concurrent
  long-running-request limit is retried; the daily limit is reported as a quota error, not a permissions error.
- **API version is in every record** (`attributes.url`), pinned at `v66.0`; bumping it rewrites that key on every
  stored record at the next pull.
- Ids are compared/ordered by SOQL directly; the 18-character form is what's stored.
