# DEV-10437 — Enforce `x-scratch-write-once` / `x-scratch-readonly` on nested subfields

**Status:** Plan (pre-implementation)
**Branch:** `dev-10437-validator-does-not-enforce-write-once-readonly-on-nested` (off `origin/master` @ 308ace7ed)
**Size:** XS
**Single file of behavior change:** `scratch-git-2/src/shared/validators/builtin.rs`

## Problem

`enforce_schema` (the scratch-git Rust validator used by the CLI / git-push publish
path) reads `x-scratch-write-once` and `x-scratch-readonly` only off the **top-level**
entries of `schema.properties`. Both the readonly loop (lines ~280–326) and the
write-once loop (lines ~334–361) do:

```rust
if let Some(properties) = schema_obj.get("properties").and_then(|v| v.as_object()) {
    for (field_name, props) in properties {   // top-level keys ONLY
        if props.get("x-scratch-write-once")... != Some(true) { continue; }
        ...
    }
}
```

They never descend into a nested object's own `properties`. So for a schema like:

```jsonc
"properties": {
  "location": {
    "type": "object",
    "properties": {
      "address": { "type": "string" },
      "lat": { "type": "number", "x-scratch-write-once": true },
      "lng": { "type": "number", "x-scratch-write-once": true }
    }
  }
}
```

the desktop grid locks the `location.lat` cell on existing records (via
`TableViewSubfield.writeOnce`, derived from the same schema), but the Rust validator
emits **no** advisory when `location.lat` changes on an existing record. The two
enforcement sites disagree. `x-scratch-readonly` has the identical top-level-only gap.

This is **latent, not a regression**: no connector marks a *subfield* write-once today
(Attio's write-once fields — `parent_record_id`, `parent_object`, `content_plaintext`
— are all top-level strings). We are closing the boundary before a connector relies on it.

## Consistency anchor (why dot-path is correct)

- The single source of truth is the schema's `x-scratch-*` annotation on the property
  node. The desktop's `TableViewSubfield.writeOnce` is *built from* that same annotation,
  so reading the schema directly in the validator keeps the two sites in agreement by
  construction.
- The JSONSchema conformance branch in this same function already emits nested
  `field_path`s as dot paths (`pointer.trim_start_matches('/').replace('/', ".")` → e.g.
  `location.lat`). Emitting `location.lat` for the readonly/write-once checks matches that
  existing convention, so a single record's violations all read with one path grammar.

## Design

### Core idea

Replace each top-level `for (field_name, props) in properties` loop with iteration over a
**flat list of every annotated-or-not property at every depth**, produced by one recursive
walk of `properties`. Keep the *value comparison* logic byte-for-byte identical to today —
only the set of (path, node) pairs being checked grows, and value lookup becomes nested.

### Helper 1 — recursive property collector

```rust
/// Walks a JSON-Schema `properties` object and yields every property node at every
/// depth, paired with its path segments from the schema root. Descends into any node
/// that itself has an object-typed `properties` map (a nested object schema). Order is
/// a stable pre-order so output is deterministic for tests.
///
/// `depth_budget` guards against a pathological schema; JSON Schemas generated by the
/// connectors are plain acyclic trees (no `$ref`), so this never fires in practice — it
/// only bounds a hand-authored or malformed schema.
fn collect_schema_properties<'a>(
    properties: &'a serde_json::Map<String, serde_json::Value>,
    prefix: &[String],
    depth_budget: usize,
    out: &mut Vec<(Vec<String>, &'a serde_json::Value)>,
) {
    for (field_name, node) in properties {
        let mut path = prefix.to_vec();
        path.push(field_name.clone());
        out.push((path.clone(), node));
        if depth_budget > 0 {
            if let Some(child) = node.get("properties").and_then(|v| v.as_object()) {
                collect_schema_properties(child, &path, depth_budget - 1, out);
            }
        }
    }
}
```

- Carries **path *segments*** (`Vec<String>`), not a pre-joined dotted string. This avoids
  the dot-ambiguity bug a join-then-split would introduce when a property key itself
  contains a `.` — we navigate values by the exact segments and only join for display.
- Yields the parent object node too (e.g. `location`), preserving today's behavior where a
  top-level object can itself be annotated.

### Helper 2 — nested value lookup by segments

```rust
/// Follows `path` segment-by-segment through nested JSON objects. Returns `None` if any
/// intermediate is absent or not an object — mirroring today's `record.get(name)` miss.
fn get_by_segments<'a>(
    value: &'a serde_json::Value,
    path: &[String],
) -> Option<&'a serde_json::Value> {
    let mut current = value;
    for segment in path {
        current = current.get(segment)?;
    }
    Some(current)
}
```

(`serde_json::Value::get` on a non-object returns `None`, so a scalar/array intermediate
naturally yields `None` — no explicit object-type check needed.)

### Rewire the two checks

Build the collected list once and reuse it for both loops:

```rust
let collected: Vec<(Vec<String>, &serde_json::Value)> =
    match schema_obj.get("properties").and_then(|v| v.as_object()) {
        Some(properties) => {
            let mut out = Vec::new();
            collect_schema_properties(properties, &[], MAX_SCHEMA_RECURSION_DEPTH, &mut out);
            out
        }
        None => Vec::new(),
    };
```

- **Readonly loop:** iterate `&collected`; for each node whose `x-scratch-readonly == true`,
  run the *existing* existing-record-diff / new-record-set logic, but read `working` via
  `get_by_segments(&ctx.record, &path)` and `master_val` via
  `get_by_segments(master, &path)`. `field_path` = `path.join(".")`.
- **Write-once loop:** same, gated on `x-scratch-write-once == true`, with the existing
  new-record-skip / existing-record-diff logic, nested lookups, `field_path = path.join(".")`.

The two loops keep their *distinct* semantics (readonly warns when set on a new record;
write-once is clean on a new record) — only the iteration source and value lookup change.

`MAX_SCHEMA_RECURSION_DEPTH`: a module const (e.g. `32`). Generous; purely a backstop.

### What deliberately stays the same

- The required check and JSONSchema-conformance branch are untouched (the required array is
  top-level-only by JSON Schema definition; conformance already recurses via `iter_errors`).
- The dedup-by-`field_path` tail keeps working — nested paths are distinct strings, so no
  collisions with top-level paths.
- Value-comparison rules, message/description strings, warning levels: unchanged. A reviewer
  diffing the warning text for a *top-level* field must see zero change.

## Scope boundaries (explicit non-goals)

1. **Arrays / `items` are out of scope.** A write-once annotation inside
   `properties.tags.items.properties.x` is *not* enforced. The issue scope says "recurse
   into nested object `properties`"; array element indexing (path `tags.0.x`) is a separate,
   larger design (which index? all? ragged arrays vs master) and no connector needs it. The
   code will simply not descend through `items`. **This will be called out in the doc + a
   code comment** so it is a known boundary, not a silent miss.
2. **`additionalProperties` / `patternProperties` schemas** are not walked (same reasoning —
   no static property name to annotate).
3. **No new server publish-pipeline enforcement.** The issue's "Related (lower priority)"
   note — that there is no generic server-side write-once *enforcement*, only per-connector
   field selection — is explicitly **not** addressed here. The validator advisory is, and
   remains, advisory. (Could be filed as a separate item; flagged, not done.)
4. **`$ref` resolution** is not added; connector schemas are inlined.

## Edge cases & how they resolve

| Case | Behavior |
| --- | --- |
| Parent object `location` *and* child `location.lat` both annotated | Two separate warnings (`location`, `location.lat`). Acceptable; connectors don't double-mark. Documented. |
| Intermediate object is `null`/absent in working or master | `get_by_segments` returns `None`; comparison mirrors today's top-level "master missing field" path (documented by existing `readonly_master_missing_field_no_violation`). |
| Leaf unchanged but sibling changed | Only the changed leaf path warns. |
| Deeply nested (≥2 levels) | Full dot path emitted (proves true recursion, not one-level special-casing). |
| No `properties` key | `collected` is empty; both loops no-op (today's behavior). |

## Test plan (all in the existing `#[cfg(test)] mod tests` of `builtin.rs`)

Add a `schema_with_nested_write_once` / `schema_with_nested_readonly` helper mirroring the
existing `schema_with_write_once`, then:

1. `nested_write_once_changed_on_existing_is_warning` — `location.lat` changes vs master →
   exactly 1 warning, `field_path == "location.lat"`, message `"Updated write-once field"`.
2. `nested_write_once_unchanged_on_existing_is_clean`.
3. `nested_write_once_set_on_new_record_is_clean` — new record (no master), nested value set → clean.
4. `nested_readonly_changed_on_existing_is_warning` — `field_path == "location.lat"`.
5. `nested_readonly_set_on_new_record_is_warning`.
6. `deeply_nested_write_once_changed_is_warning` — `a.b.c` (2 levels) changed → 1 warning,
   `field_path == "a.b.c"` (recursion depth proof).
7. `nested_intermediate_object_absent_in_master_behaves_like_top_level` — documents the
   null/absent-intermediate semantics (1 warning, consistent with existing top-level test).
8. `collect_schema_properties_yields_nested_paths` — unit test on the helper: a 2-level
   schema yields the expected `(segments, node)` set including both parent and leaves.
9. Regression: existing top-level readonly/write-once/required tests must remain green
   unchanged (no edits to them).

## Risk assessment

- **Blast radius:** one function's two inner loops + two small private helpers + tests, all
  in `builtin.rs`. No public API/signature change. No DB/migration/wire change.
- **Behavioral risk:** top-level paths must produce byte-identical output. Guarded by the
  unchanged existing tests + the requirement that value-comparison code is copied verbatim.
- **Worst latent bug to avoid:** path/value desync (display path ≠ navigated path). Mitigated
  by carrying segments end-to-end and only joining for display.

## Post-codex-review scope decision (2026-06-22)

Codex adversarially reviewed this plan and surfaced three real issues. Per maintainer
decision, the main fix ships **now** scoped to **direct nested object `properties`**, and the
three issues are split into separate fast-follow tickets (all assigned to Ivan). This is safe
because **all three are latent today** — no connector annotates any nested subfield yet, so
the main change introduces no live regression.

- **DEV-10493** (Medium) — a nested readonly/write-once **Warning** can mask a JSONSchema
  **Error** at the same dot-path via the dedup-keep-last step. Fix later: severity-aware
  precedence (keep the error, or surface both).
- **DEV-10494** (Medium) — the collector walks only **direct** `properties`; subfields inside
  an `anyOf`/`oneOf` nullable-object union are not enforced, though the desktop grid enforces
  them. Fix later: reuse the `anyOf`/`oneOf` walk to descend into the non-null object member.
- **DEV-10495** (Low) — `field_path = segments.join(".")` can collide a literal-dot key with a
  nested path; dedup then drops one. Fix later: dedup on the segment vector, keep dot-join as
  display-only.

What shipped in this change: `collect_schema_properties` (direct-`properties` recursion only)
+ `get_by_segments`, both readonly and write-once loops rewritten over the collected list,
nested-happy-path tests, and **scope-boundary negative tests** that lock the array-`items` and
`anyOf`-member non-enforcement so closing those gaps later is a deliberate, tested change.
