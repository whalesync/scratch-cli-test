Reading these
A (diff table) is the strongest default: the whole row is the context, changed cells light up in place, and short changes (price, inventory) are fully legible without drilling. Long fields (descriptions) show a one-line redline preview and open a drawer for the full diff — overview stays put behind, ✕ returns you exactly where you were.

B (grouped by type) matches the mental model when an edit is really one operation — "I lowered 34 prices." It surfaces the pattern (28 down, avg −9%) and lets you approve a whole class at once, which A can't.

My recommendation: build A as the home with the drawer drill-in, and offer B's grouping as a toggle ("Table / By type") on the same data — they're two lenses on one change set. Tell me which to make interactive.
